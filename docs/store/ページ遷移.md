Nuxt.js（Nuxt 3）とPiniaを組み合わせた環境において、ストアのデータがクリアされる（初期化される）タイミングは、「アプリケーションの実行環境（状態）がリセットされるかどうか」によって決まります。

結論から言うと、Nuxtのアプリケーションが「SPA（Single Page Application）として動いている間」はデータは保持**され、**「ページ全体がリロード（再読み込み）された時」にデータはクリアされます。

提示いただいたページ遷移例と合わせて、具体的なクリアタイミングを解説します。

---

## 1. ページ遷移例におけるデータの挙動

ご提示いただいた `/service` 配下の遷移において、それぞれの挙動は以下のようになります。

| 遷移方法                 | データの挙動                     | 理由                                                                                      |
| ------------------------ | -------------------------------- | ----------------------------------------------------------------------------------------- |
| **1. `MapsTo` での遷移** | **保持される**（クリアされない） | Nuxtの JavaScript プロセスが維持されたまま、メモリ上でページを切り替える（SPA遷移）ため。 |

| **2. 直接リンクでの遷移**<br>

<br>※ `<NuxtLink>` を使用 | **保持される**（クリアされない） | `MapsTo` と同様、Nuxtのルーターを介したSPA遷移になるため。 |
| **3. 直接リンクでの遷移**<br>

<br>※ `<a>` タグやURL直接入力 | **クリアされる** | ブラウザがページ全体を完全にリロード（ハードリフレッシュ）し、JavaScriptのメモリが解放されるため。 |
| **4. リダイレクト**<br>

<br>※ `MapsTo(url, { redirectCode: 302 })` 等 | **サーバー側かクライアント側かで変わる** | 詳細は後述（基本はSPA遷移なら保持、初期リクエスト時ならリセット）。 |

---

## 2. データがクリアされる具体的なタイミング

Piniaのストアデータがクリアされるのは、主に以下の3つのタイミングです。

### ① ブラウザのリロード（F5キー、URLの直接入力・エンター）

ユーザーがブラウザの更新ボタンを押したり、アドレスバーに直接URLを入力して移動した場合、ブラウザ上のJavaScript実行環境が完全にリセットされます。Piniaのデータはメモリ上に保存されているため、このタイミングで全て初期化（クリア）されます。

### ② `window.location.href` を使った遷移

Nuxtのルーター（`MapsTo` や `<NuxtLink>`）を使わず、JavaScriptの `window.location.href = '/service/users'` を使って遷移した場合、ブラウザが通常の画面遷移（再読み込み）を行うため、データはクリアされます。

### ③ SSR（サーバーサイドレンダリング）時の注意点（初期リクエスト）

ユーザーが最初にサイトにアクセスした時（またはリロードした時）、Nuxtはサーバー側で一度Piniaのストアを生成し、それをクライアント（ブラウザ）側に引き継ぎます（State Hydration）。
サーバー側で生成されたストアは、そのリクエストの処理が終わると消滅（クリア）します。ブラウザ側にはその時点のデータが引き継がれますが、サーバー側のメモリにデータが残り続けることはありません。

---

## 3. リダイレクト時の注意点

リダイレクト（`MapsTo` をミドルウェアなどで利用する場合）は、「そのリダイレクトがいつ発生したか」によって挙動が異なります。

- **初回のページアクセス時（SSR時）のリダイレクト:**
  まだブラウザにアプリケーションがロードされていない状態のため、リダイレクト先のページで新しくPiniaストアが構築されます（実質クリアされた状態からスタート）。
- **画面を操作している最中（CSR/SPA時）のリダイレクト:**
  `MapsTo` によるリダイレクトであれば、SPA遷移として処理されるため、**ストアのデータは保持**されます。

---

## 💡 データを意図的にクリア・保持したい場合の対策

### データを意図的にクリアしたい場合（ページ離脱時など）

Nuxtのページコンポーネントがアンマウントされる際や、ミドルウェアを使って手動でクリアする必要があります。

```typescript
// Piniaには標準で初期状態に戻す $reset() メソッドがあります
const store = useMyStore()

// ページを離脱するときにクリアする場合
onUnmounted(() => {
  store.$reset()
})

```

### 画面リロード後もデータを保持したい場合（永続化）

ブラウザをリロードしてもデータを消したくない場合（ユーザーのログインセッションやカート情報など）は、`localStorage` や `Cookie` にデータを同期させる必要があります。
Nuxt/Pinia環境では、**`@pinia-plugin-persistedstate/nuxt`** というプラグインを導入するのが最も一般的で簡単です。

Nuxt.js（特にNuxt 3）のアプリケーションにおいて、これまで挙げた「通常のSPA遷移」「直接入力」「リダイレクト」のほかに想定されるページ遷移パターンと、それぞれのPiniaストアの挙動（クリアされるか保持されるか）をまとめました。

実務で特によく遭遇するケースは以下の4つです。

## 4. そのほかに想定される遷移パターン

### ① 外部サイトへ行ってから「戻る」ボタンで戻ってきた場合

- **データの挙動：** **クリアされる**（初期化される）
- **解説：** ユーザーが一度 `/service/users` から外部サイト（例: Googleや決済画面など）に遷移し、ブラウザの「戻る」ボタンで戻ってきた場合です。ブラウザのキャッシュ（Bfcache）が効く場合もありますが、Nuxtアプリケーションとしては再度イチから立ち上がる（SSRまたは初期ロードが発生する）ため、**Piniaのデータは原則クリア**されます。
  > 💡 **例外（セッション維持）：** 外部決済連携などでデータを維持したい場合は、遷移前に `Cookie` や `localStorage` に退避させるか、Stateをクエリパラメータに持たせる必要があります。

### ② ブラウザの「戻る・進む」ボタンでの遷移（サイト内）

- **データの挙動：** **保持される**（クリアされない）
- **解説：** 同じサイト内（例：`/service/users` から `/service/functions` へ移動した後、ブラウザの「戻る」ボタンを押した場合）の移動であれば、Nuxtのルーターが履歴（History API）をハンドリングするため、**SPA遷移となりデータは保持**されます。

### ③ クエリパラメータやハッシュ（#）のみの変更

- **データの挙動：** **保持される**（クリアされない）
- **解説：** `/service/users?page=1` から `/service/users?page=2` や、`/service/users#section1` のような遷移です。ページコンポーネントそのものが再利用されるため、Piniaのデータは完全に維持されます。

### ④ エラーページ（404や500）への遷移、およびそこからの復帰

- **データの挙動：** **実装方法によって変わる**
- **解説：** \* `showError`（Nuxt 3の標準関数）を使ってエラー画面に飛ばした場合、または `clearError` で元のページに戻した場合は、**SPAのコンテキストが維持されるため、データは保持**されます。
- ただし、サーバー側で致命的なエラーが発生し、ブラウザが完全にエラー画面をリロードして表示した場合は、**データはクリア**されます。

## 📌 まとめ（クリア可否の一覧表）

これまでの内容を含め、開発中に発生する遷移パターンとPiniaの挙動を一覧に整理しました。

| 遷移パターン                                | ストアデータ | 分類・補足                                       |
| ------------------------------------------- | ------------ | ------------------------------------------------ |
| `MapsTo()` での遷移                         | **保持**     | 通常のSPA遷移                                    |
| `<NuxtLink>` での遷移                       | **保持**     | 通常のSPA遷移                                    |
| ブラウザの「戻る・進む」（サイト内）        | **保持**     | History APIによるSPA遷移                         |
| クエリ・ハッシュの変更 (`?page=2` など)     | **保持**     | 同一コンポーネント内の移動                       |
| `showError` / `clearError` での画面切り替え | **保持**     | Nuxtの内部エラーハンドリング                     |
| **`MapsTo` のリダイレクト (CSR時)**         | **保持**     | 画面操作中のミドルウェア等によるリダイレクト     |
| **`MapsTo` のリダイレクト (SSR時)**         | **クリア**   | 初回アクセス時のリダイレクト（新しくストア生成） |
| URL直接入力・F5リロード                     | **クリア**   | JavaScriptメモリの解放                           |
| `<a>` タグによる遷移                        | **クリア**   | 通常のHTML遷移（再読み込み）                     |
| `window.location.href` による遷移           | **クリア**   | JavaScriptによる強制リロード遷移                 |
| 一度外部サイトへ遷移し、「戻る」で復帰      | **クリア**   | アプリケーションの再起動                         |
